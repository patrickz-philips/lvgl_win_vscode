# 构建说明

本文档描述根目录 CMake 工程和批处理脚本实际实现的 Windows 构建流程。程序操作和模块 API 参见[使用说明](使用说明.md)。

## 可用项目

| 项目参数 | 功能 | 默认窗口 |
| --- | --- | --- |
| `HAIR_DRYER` | 吹风机控制和灯带动画 | 800 x 720 |
| `CHEETAH` | 小型数字组件 | 96 x 96 |
| `SLIDE_PLAYER` | 32 张图片滑动浏览 | 466 x 466 |
| `BATTERY_MONITOR` | 两页电池状态显示 | 410 x 502 |
| `ACC_DATA` | 三轴加速度曲线 | 410 x 502 |

脚本和 CMake 的遗留选择列表仍接受 `SMART_SHAVER`，但当前仓库没有对应源码目录，因此不能成功构建。

## 环境要求

- Windows 10 或更高版本。
- CMake 3.12.4 或更高版本，并已加入 `PATH`。
- CMake 支持的 C/C++ 工具链，例如 Visual Studio Build Tools。
- vcpkg 位于仓库同级目录 `..\vcpkg`。
- 已为 `x64-windows-static` triplet 安装 SDL2。
- 仅在重新生成 Hair Dryer C 资源时需要 Python 3 和 Pillow。

`build.bat` 固定使用 `..\vcpkg\scripts\buildsystems\vcpkg.cmake`。如果 vcpkg 安装在其他位置，需要修改脚本中的 `VCPKG_TOOLCHAIN`，或手动配置 CMake。

可在仓库根目录执行以下命令安装 vcpkg 和 SDL2：

```batch
cd ..
git clone https://github.com/microsoft/vcpkg.git
vcpkg\bootstrap-vcpkg.bat
vcpkg\vcpkg.exe install sdl2:x64-windows-static
cd lvgl_win_vscode
```

检查环境：

```batch
cmake --version
..\vcpkg\vcpkg.exe list
```

## 构建

在仓库根目录执行：

```batch
build.bat [PROJECT] [Debug|Release]
```

两个参数都可省略，默认值为 `HAIR_DRYER Debug`；参数不区分大小写。

```batch
build.bat
build.bat CHEETAH Debug
build.bat SLIDE_PLAYER Release
build.bat BATTERY_MONITOR Debug
build.bat ACC_DATA Release
```

脚本先配置独立的 CMake 构建树，再编译 `main` 可执行文件。不同项目和配置互不覆盖：

```text
build/<Debug|Release>/<project>/
bin/<Debug|Release>/<project>/main.exe
```

例如 `build.bat ACC_DATA Debug` 输出 `bin\Debug\acc_data\main.exe`。

### Hair Dryer 资源

Debug 构建在运行时读取 `projects/hair_dryer/assets/hair_dryer.png`。应通过 `run.bat` 启动，使工作目录保持为仓库根目录。

Release 构建把 `projects/hair_dryer/assets/hair_dryer.c` 编入程序。如果该文件不存在，构建脚本会在 CMake 配置前执行转换：

```batch
python -m pip install pillow
python projects\hair_dryer\assets\convert_image.py
```

当前仓库已经包含生成后的 C 文件。`CHEETAH` 和 `SLIDE_PLAYER` 在 Debug、Release 中都使用静态 C 图片；如果 `projects/slide_player/assets` 下没有数字命名的 C 资源，Slide Player 会在配置阶段报错。

## 运行

运行参数必须与已经构建的项目和配置一致：

```batch
run.bat BATTERY_MONITOR Debug
```

脚本检查 `bin\<配置>\<项目>\main.exe`，并以仓库根目录作为工作目录启动。具体交互和数据接口参见[使用说明](使用说明.md)。

## 清理

```batch
clean.bat [TARGET]
```

| 目标 | 删除内容 |
| --- | --- |
| `all` 或省略参数 | 整个 `build` 和 `bin` 目录 |
| `build` | 整个 `build` 目录 |
| `bin` | 整个 `bin` 目录 |
| 项目参数 | 该项目在 `build`、`bin` 下的 Debug 和 Release 目录 |

```batch
clean.bat ACC_DATA
clean.bat build
clean.bat all
```

## 手动使用 CMake

每个项目和配置应使用独立构建目录。以下命令等价于 Hair Dryer Debug 脚本构建：

```batch
cmake -B build\Debug\hair_dryer ^
  -DCMAKE_BUILD_TYPE=Debug ^
  -DSELECTED_PROJECT=HAIR_DRYER ^
  -DVCPKG_TARGET_TRIPLET=x64-windows-static ^
  -DCMAKE_TOOLCHAIN_FILE="..\vcpkg\scripts\buildsystems\vcpkg.cmake"
cmake --build build\Debug\hair_dryer --config Debug -j
```

常用可选参数：

| 参数 | 默认值 | 用途 |
| --- | --- | --- |
| `USE_FREERTOS` | `OFF` | 构建实验性的 FreeRTOS 主机路径 |
| `LVGL_PRO_PROJECT_DIR` | 空 | 加入包含 `CMakeLists.txt` 的 LVGL Pro 工程 |
| `LV_USE_LIBPNG` | `OFF` | 从工具链链接 libpng |
| `LV_USE_LIBJPEG_TURBO` | `OFF` | 从工具链链接 libjpeg-turbo |
| `LV_USE_FREETYPE` | `OFF` | 从工具链链接 FreeType |

常规项目构建会关闭 LVGL examples、demos 和内部 ThorVG。窗口尺寸由所选模块头文件定义；修改尺寸时需要同时保持模块布局和 CMake 定义一致。

## 常见问题

### 找不到 CMake

安装 CMake 后重新打开终端，并执行 `cmake --version`。如果 `PATH` 中没有 CMake，`build.bat` 会在配置前停止。

### 找不到 vcpkg 工具链

确认仓库根目录的相对路径 `..\vcpkg\scripts\buildsystems\vcpkg.cmake` 存在。

### 找不到 SDL2

安装脚本使用的静态 triplet：

```batch
..\vcpkg\vcpkg.exe install sdl2:x64-windows-static
```

### CMake 复用了旧项目配置

每个项目都有独立缓存，只清理受影响的项目后重新构建：

```batch
clean.bat SLIDE_PLAYER
build.bat SLIDE_PLAYER Debug
```

### Hair Dryer 图片转换失败

用脚本实际调用的 Python 安装 Pillow，再重新构建。转换失败不会中止脚本，但缺少生成的 C 文件时，Release 会退回文件系统加载。

### 找不到可执行文件

传给 `run.bat` 的项目和配置必须与成功构建时一致。检查 `bin` 下的目标路径，或重新构建对应组合。
