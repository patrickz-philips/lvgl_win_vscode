# Spec 输入规范

本文件规定**用户如何提出一项新工作**。`/pz-feature-workflow` 会要求你按下面的模板填写，`analyzer` 在字段补齐前不会开始 plan。

其他三类工作用各自的专用模板（写在入口 prompt 里），但 §2 的确认清单同样适用：

| 工作类型 | 入口 | 用什么模板 |
| --- | --- | --- |
| 新功能 | `/pz-feature-workflow` | 本文件 §3 |
| 界面改动 | `/pz-ui-workflow` | 本文件 §3 + 状态矩阵 / 屏幕尺寸与布局 / 输入映射额外字段 |
| 缺陷修复 | `/pz-bugfix-workflow` | 缺陷专用模板（复现步骤 / 期望 vs 实际） |
| 重构 | `/pz-refactor-workflow` | 重构专用模板（痛点 / 安全网 / 可度量目标） |

## 使用方式

1. 在 chat 中运行对应的入口 prompt。
2. 复制 §3 的模板，填好后贴回 chat（可以只填必填项，其余由 analyzer 追问）。
3. analyzer 用 `brainstorming` skill 与你确认**输入契约**和**输出契约**，双方确认后才进入 plan。

## 1. 字段说明

| 字段 | 必填 | 说明 | 反例 |
| --- | --- | --- | --- |
| 功能名称 | ✅ | 一句话，可直接转成 `<type>-<kebab-slug>` | 「优化一下」 |
| 背景 / 问题 | ✅ | 现在什么不work，谁在受影响 | 只写解决方案不写问题 |
| 目标用户与场景 | ✅ | 谁、在什么情况下、要达成什么 | 「所有人都用得到」 |
| In scope | ✅ | 必须实现的行为，逐条可勾选 | 「以及相关的一切」 |
| Out of scope | ✅ | 明确不做的事，防止范围蔓延 | 留空 |
| 输入契约 | ✅ | 数据来源、字段、类型、必填性、取值范围、非法输入的处理 | 「传个对象进去」 |
| 输出契约 | ✅ | 返回/渲染/落库的结构、成功态、失败态、副作用 | 「返回结果」 |
| 验收标准 | ✅ | Given / When / Then，可被自动或手动执行 | 「体验流畅」 |
| 约束 | ⬜ | 技术栈、性能、安全、兼容性、可访问性 | — |
| 依赖与影响面 | ⬜ | 依赖的模块/服务，可能被影响的既有功能 | — |
| 未决问题 | ⬜ | 你也没想清楚的点，会在 brainstorming 中澄清 | — |
| 优先级 / 规模 | ⬜ | P0-P2；S/M/L | — |

## 2. 输入输出标准确认清单

进入 plan 前，analyzer 必须与你逐项确认到「无 `TBD`」：

- [ ] 每个输入字段都有：名称、类型、是否必填、取值范围/枚举
- [ ] 非法输入、空输入、边界值的期望行为已定义
- [ ] 输出的成功结构已定义（字段、类型）
- [ ] 输出的失败结构已定义（错误码/错误信息/降级行为）
- [ ] 副作用已列明（写库、发请求、改文件、埋点）
- [ ] 每条验收标准都能对应到一条可执行的验证命令或手动步骤
- [ ] 性能 / 安全 / 兼容性中不适用的项已显式标注「不适用」而不是留空

## 4. 填写示例（节选）

```markdown
## 功能名称
Battery Monitor 低电量告警

## 背景 / 问题
电量低于阈值时界面没有任何提示，用户直到设备关机才发现。硬件侧已能提供电量百分比。

## In scope
- [ ] 电量 ≤ 15% 时电量数值转为告警色并闪烁
- [ ] 电量恢复到 > 15% 时自动回到常态显示

## Out of scope
- 蜂鸣器/震动提醒、关机保护逻辑、阈值可配置

## 输入契约
| 输入 | 来源 | 类型 | 必填 | 取值范围 | 非法值行为 |
| --- | --- | --- | --- | --- | --- |
| `data->bat_percent` | `battery_monitor_set_data()` | `uint8_t` | 是 | 0-100 | > 100 钳制到 100，不触发告警状态切换 |
| `data` | 宿主应用（LVGL 线程） | `const battery_monitor_data_t *` | 是 | 非 NULL | NULL 直接返回，UI 不变 |

## 输出契约
| 场景 | 输出 | 结构 / 类型 | 副作用 |
| --- | --- | --- | --- |
| 电量 > 15% | 常态显示 | 电量标签使用默认色 | 停止闪烁动画（若在跑） |
| 电量 ≤ 15% | 告警显示 | 电量标签使用告警色 + 闪烁 | 创建/复用一个 `lv_anim`，不新建定时器 |
| 入参 NULL | 无输出 | — | 无 |

## 验收标准
1. Given 已 `battery_monitor_ui_init()`，When 推入 `bat_percent = 12`，Then 电量标签变告警色并开始闪烁
2. Given 处于告警态，When 推入 `bat_percent = 40`，Then 恢复默认色且闪烁停止
3. Given 处于告警态，When 传入 `NULL`，Then 显示完全不变且不崩溃
```

## 5. 常见问题

**spec 太小要不要走全流程？** 只改一行、无行为变化的改动走 `/pz-quick-fix`（它会先做准入判定，不够小会把你打回正式入口）。只要有可观察的行为变化，就走工作流。

**想不清楚输入输出怎么办？** 填 `TBD` 并写进「未决问题」，`brainstorming` 阶段会把它逼出来；但带 `TBD` 不能进入 plan。

**能不能中途改 spec？** 可以，但要显式说明，analyzer 会更新 `docs/work/<feature-id>/spec.md` 并重跑 `plan-pre-review`。
